# Seed Problems — актуальний статус `prisma/seed.sql`

Дата останньої перевірки: 2026-05-26.

Цей файл був рев'ю перед демо. Усі змістові проблеми, які могли виглядати дивно в інтерфейсі, виправлено в `prisma/seed.sql`.

## Виправлено

| # | Було | Статус |
|---|------|--------|
| 1 | `notification_organization` мав повідомлення, які не збігалися з `type` / `actor_id` / `project_id` / `organization_id` | Виправлено: фінальні тексти 1–15 відповідають своїм рядкам |
| 2 | Pending approval-події могли виглядати так, ніби вже мають заявки учасників | Виправлено: pending approval-проєкти 30–31 не мають `project_registration` |
| 3 | Новини без фото або з битими/невідповідними фото | Виправлено: усі news мають фото; зовнішні image URL перевірені |
| 4 | `organization_membership_request` мав `LEAVE` від користувачів, які не були членами відповідної організації | Виправлено: `LEAVE`-флоу прибрано з seed повністю, бо вихід з організації миттєвий |
| 5 | `donation.donor_name` містив ініціали від старих імен | Виправлено: донорські імена узгоджені з фінальними іменами акаунтів |
| 6 | `app_user.points` не враховував нові `points_transaction` | Виправлено: дельти балів синхронізовані з EARN / SPEND / BONUS / PENALTY / ADJUSTMENT |
| 7 | `DEMO_DATA.md` міг розійтися по балах Анни | Виправлено в seed: у Анни нові транзакції дають net 0, тому 120 балів лишається коректним |
| 8 | Два різні app_user мали однаковий pravatar `img=13` | Виправлено: дубля app_user-аватарів немає |
| 9 | Проєкт 29 мав `participants = 0` | Виправлено: встановлено реальну місткість 18 |
| 10 | Частина банерів повторювалася 4–5 разів | Виправлено: високочастотні повтори розведені; лишилися тільки тематичні повтори до 3 разів |

## Перевірено

- `npx prisma validate` — схема валідна.
- `git diff --check -- prisma\seed.sql docs\SEED_PROBLEMS.md docs\DEMO_DATA.md` — whitespace-помилок немає.
- SQL-баланс лапок і дужок у `seed.sql` — нормальний.
- Старі проблемні імена, ініціали й назви з попереднього рев'ю більше не трапляються в seed.
- Усі зовнішні media/PDF URL із seed (`pravatar`, `ui-avatars`, `unsplash`, `pexels`, `cloudinary`) повертають коректний 2xx і очікуваний content-type.
- `organization_membership_request`: 28 рядків, дублів по `(organization_id, user_id)` немає.
- `project_registration`: pending approval-проєкти не мають заявок учасників.
- `notification_organization`: фінальні тексти збігаються з відповідними сутностями.
- `points_transaction`: нові транзакції синхронізовані з `app_user.points`.

## Залишковий операційний ризик

Медіа все ще завантажуються із зовнішніх CDN (`pravatar`, `ui-avatars`, `unsplash`, `pexels`, `cloudinary`). Це не проблема якості seed-текстів і не бита URL-проблема: перевірені image URL працюють. Але для офлайн-демо або нестабільної мережі краще окремо кешувати критичні зображення локально або в одному контрольованому бакеті.
